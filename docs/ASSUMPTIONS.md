## Принятые решения

### Бренд и дизайн
- **Приоритет у брендбука** (`D:\nobel\brend\gaidbook`). Цвет `#294a8e` из первого ТЗ не используется. Hero, шапка, футер — Noble Night `#234F71` и производные; Royal Sand `#EFCD9C` только на тёмном фоне (контраст 5,7:1). На белом фоне для акцентного текста используется `sand-700 #8A6A3A` (5,0:1).
- **Грузинский шрифт**: в Bahnschrift и Stolzl грузинского нет. Используется **Noto Sans Georgian** (OFL), локально, только грузинский поднабор глифов. Браузер подставляет его автоматически для грузинских символов (второй шрифт в каждом стеке), поэтому латиница и цифры на грузинских страницах остаются фирменными.
- **Грузинские заглавные (мтаврули)**: CSS `text-transform: uppercase` превращает грузинский текст в мтаврули. Для подписей-eyebrow это оставлено (типографически корректно), но разрядка уменьшена до 0,06em. Носителю стоит подтвердить, что это выглядит уместно.
- **Логотип**: используются готовые WebP из `logo/Web`. Исходный SVG — артборд со всеми версиями сразу, вырезать из него вручную рискованно (запрет брендбука на искажения). Нужны отдельные SVG-экспорты → `CONTENT_TODO.md`.
- Лента корон: PNG из «Стилеобразующие элементы/Web», ужата до высоты 32 px и повторяется по горизонтали.
- Стили: **Tailwind CSS 4** (выбран вместо SCSS), токены в `@theme` в `web/src/styles.css`.

### Языки и маршруты
- Язык по умолчанию **ka**. Порядок переключателя KA · RU · EN.
- `/` → язык по `Accept-Language` (сервер Node: `web/src/server.ts`; статика Cloudflare Pages: Pages Function, этап 7). В prerender-HTML корня — мета-редирект на `/ka`.
- Адреса без языка (`/services/ppf-full`) перенаправляются на `/ka/...`.
- Slug латиницей, одинаковые для всех языков.
- `/book` при `features.leadForm = false` перенаправляет на `/contacts` (в Angular и в `public/_redirects` для Cloudflare).

### Данные
- Прайс из брифа внесён как **реальные** данные. В модель `PriceVariant.key` добавлен вариант `standard` («все автомобили») для шумоизоляции, где цена делится не по кузову, а на «обычные» и «Defender, G-Class».
- Цены форматируются собственной функцией (`core/i18n/format.ts`), а не `Intl`, чтобы строка была одинаковой на сервере и во всех браузерах: `$1 300`, `700 ₾`; в английском разделитель тысяч — запятая.
- Координаты: из карточки Google `41.7551996, 44.7669368`. Ссылка Яндекса построена по его координатам `41.755064, 44.766503` (разница десятки метров).
- Telegram: `null` и `features.telegram = false`. Ссылка `t.me/+995510100999` из первого промта была неверной и удалена.
- Рейтинг Google 4,9 / 57 — в `site.json`, обновляется вручную (поле `updated`).
- **Отзывы** вносятся вручную в `reviews.json`: текст и имя как в Google, без правок и перевода; на страницах других языков показывается пометка «Оригинал: русский». Даты не указаны (в карточке Google только относительные «год назад»). Яндекс не парсится: `YandexProvider` начнёт показывать отзывы, когда в `reviews.json` появятся записи с `source: "yandex"`.
- **Рейтинг Яндекс Карт** 4,4 / 6 оценок взят вручную из публичной карточки организации (2026-10, `site.json` → `rating.yandex.updated`). У Яндекса это «оценки», а не отзывы, поэтому подпись «6 оценок». Ссылка ведёт на вкладку отзывов карточки — там же можно оставить отзыв.
- **Отзывы — карусель** на нативной прокрутке (scroll-snap): листается свайпом/колесом/клавиатурой даже без JS; кнопки «назад/вперёд» — улучшение поверх и гаснут на краях.
- **Работы без отдельных страниц** (по просьбе заказчика): карточка открывает лайтбокс, в котором можно листать фото всех машин подряд, подпись «машина · услуги». Без JS карточка открывает большое фото. Старые адреса `/{lang}/works/{id}` перенаправляются на `/{lang}/works` (Angular и `_redirects`).
- **Журнал**: 5 статей об уходе (плёнка, мойка, кожа, ткань, полировка). Только общие советы и факты из прайса (метод полировки нагревом, 2–3 дня, от 700 ₾; состав химчистки). Без названий химии и брендов. Русский — источник; ka/en — черновик ИИ (см. `I18N_REVIEW.md`). Тексты статей лежат отдельно в `data/articles/*.json` и подгружаются только на странице статьи.
- **FAQ**: 12 вопросов только по подтверждённым данным (запись, «цены от», зоны PPF, сроки, гарантия, полировка, химчистка, шумоизоляция). На страницах услуг показываются вопросы по этой услуге. Вопрос об оплате не добавлен — нет данных (вопрос 20).
- **Фото услуг**: к услугам привязаны кадры из присланных работ как иллюстрации (PPF — Panamera, BMW и Lexus; полировка — кадр с отражениями; химчистка — салон Mercedes-AMG). У экспресс-химчистки, шумоизоляции и покраски дисков фото нет — показывается фирменная заглушка.
- **Тексты о студии** («Линейный свет», «Отдельные боксы», «Моечный бокс», «Зона для клиентов») составлены по фотографиям студии. Проверьте, что всё описано верно.
- **Карта**: виджет Яндекс Карт (`site.json` → `maps.yandexWidget`) с меткой по координатам Яндекса. Грузинского интерфейса у Яндекса нет — на ka-страницах карта на английском. Под картой кнопки маршрута в Google и Яндекс. Iframe загружается лениво; адрес виден в карточке поверх карты сразу.
- Тип организации в JSON-LD: `AutoBodyShop` (ближайший подтип schema.org для оклейки и полировки).

### Техника
- Angular 22 требует Node.js ≥ 24.15; на машине разработчика Node обновлён до 24.19.
- Переводы Transloco подгружаются как lazy-чанки через `import()`, а не HTTP: одинаково работают при prerender, SSR и в браузере.
- Живой статус «Открыто до 20:00» считается только в браузере после гидрации (по времени Asia/Tbilisi). В prerender-HTML — нейтральное «Ежедневно 10:00–20:00», чтобы статическая страница не «застывала» на моменте сборки.
- Баннер cookies рендерится только в браузере. Выбор хранится в `localStorage` (необязательное удобство, с try/catch). Скрипты GA4 / Meta Pixel / GTM загружаются только после согласия.
- UTM-метки сохраняются в `sessionStorage` на время сессии.
- API не хранит заявки (нет БД): `NoopLeadRepository` только присваивает id. Персональные данные не логируются.
- Проверка `tools/check-demo.mjs` останавливает `npm run build:prod`, пока в `web/src/app/data/*.json` есть `demo: true`, поля `todo` или текст `DEMO`. Обычный `npm run build` работает (для разработки и превью).
- Для визуальной проверки используется `playwright-core` с установленным Microsoft Edge (браузер не скачивается).
- **Медиа-пайплайн на Python** (`tools/optimize-media.py`, Pillow + pillow-heif), а не Node/sharp, как предполагало ТЗ: фото студии пришли в HEIC, а sharp из npm HEIC не декодирует. Скрипт поворачивает по EXIF, удаляет метаданные (в том числе GPS), пишет WebP шириной 480–2000 px и крошечное размытое превью в `manifest.json`. AVIF не генерируется: WebP уже даёт 30–150 КБ на кадр, а `<picture>` с двумя форматами усложнил бы разметку. Добавить AVIF можно позже.
- **Переход между страницами «шторка с короной»** — View Transitions API (`withViewTransitions`): старая страница гаснет в Noble Night со знаком короны, затем проявляется новая. Только `opacity`, шапка и кнопки связи остаются на месте. Не запускается при первой загрузке, при смене только якоря/параметров и при `prefers-reduced-motion`. В браузерах без API (старые Safari/Firefox) переход просто мгновенный.
- **Канонические адреса со слэшем** (`/ru/services/ppf-full/`): prerender создаёт папки с `index.html`, и Cloudflare Pages отдаёт их по адресу со слэшем. `canonical`, `hreflang`, JSON-LD и `sitemap.xml` используют один формат.
- **sitemap.xml, robots.txt, 404.html** генерирует `tools/postbuild.mjs` по папкам prerender (входит в `npm run build:prod`).
- **Манифест медиа остаётся в основном бандле** (~10 КБ до сжатия): его используют и загрузчик картинок, и компонент `MediaFrame` (размеры и blur-превью для каждого фото). Вынос усложнил бы код ради ~3 КБ gzip.
- **SSR и allowedHosts**: Angular SSR пропускает только хосты из `angular.json` → `security.allowedHosts` (`nobledetailing.ge`, `www.nobledetailing.ge`, `localhost`). Для другого домена или превью задайте переменную окружения `NG_ALLOWED_HOSTS`, иначе сервер ответит 400.
